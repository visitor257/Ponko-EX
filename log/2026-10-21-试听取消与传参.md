# 2026-10-21 · 试听能取消了，参数也真传下去了

一份外部反馈列了 6 件事，按"不做就无法使用"排。这次做了 P0 + P1 + P2，
P3 两项（`advancedActivity`、朗读路由）没碰。记一下过程里真正卡住的地方。

---

## 1. 取消是死路：方法写好了但没人调

### 现象
用户点一下试听，得等 1~2 分钟，中途没有任何办法中断。

### 原因
`PluginSession.stopSpeaking()` 早就写好了，**整个工程里没有一处调用它**，
`PluginUiPage` 的功能按钮区也没有「停止」。

这是典型的"接口完备 ≠ 功能可用"。写完没接 UI，代码看起来一切正常，
测试也不会报错 —— 只有用户会被卡在那里。

### 做法
功能区加「停止」按钮 → `session.stopSpeaking()`。

顺带把按钮状态管起来：生成中「试听」灰、「停止」亮，反过来也一样。
不灰的话用户会连点，插件回 `BUSY`，又是一句让人困惑的错误。

## 2. 修一个死路，造出另一个死路

### 现象
加完停止按钮，点了之后状态文字停在"正在停止…"，「试听」永远是灰的，
只能退出页面重进。

### 原因
我以为取消会从 `onSpeakError` 回来 —— 毕竟 AIDL 上写着
"取消也要回一次 `onError(CANCELLED)`"。

但宿主中间还有一层：`PluginSession` 把 `CANCELLED` 当**静默收尾**处理，
**不发 `onSpeakError`**，只发一个 `onSpeakStage(Stage.CANCELLED)`。
我第一版只在 error 分支里收尾，于是那个分支永远不会被走到。

### 做法
两条路都要收尾：

```kotlin
override fun onSpeakStage(pkg, stage, label) {
    if (stage == Stage.CANCELLED) { finishRequest(); setUiHint("已取消"); return }
    // …正常进度
}
override fun onSpeakError(pkg, err) {
    if (err.code == ErrCode.CANCELLED) { finishRequest(); return }
    // …正常错误
}
```

### 教训
**"我按接口文档接了"不等于"接上了"。** 中间件可能把某个信号重新分类
（错误 → 阶段），而它的分类决定了我该在哪个回调里收尾。
改这类东西时，先去读一遍中间层怎么转发，别只看 AIDL。

## 3. 参数在接口里躺了很久，没人填

### 现象
`SynthesisRequest` 里 `mode` / `referenceAudio` / `referenceTranscript` /
`seed` / `cfg` / `timesteps` 全都有，注释写得挺详细。但宿主发请求时只填
`text` / `mode=PLAIN` / `voiceDescription`。

也就是**克隆模式在代码里存在，在用户那儿不存在**。

### 做法
插件页加一块「试听参数」：文本、模式三选一、参考音频、逐字稿、种子、线程数。

几个实现上的取舍：

**文本一开始限了 40 字 —— 这是错的，当天就撤了。** 见本文最后一节。

**只对有 TTS 能力的插件显示模式/参考音频/逐字稿。**
Echo 是 `TEST` 能力，没有克隆功能。给它摆一排点了没用的控件，
用户会以为坏了，而不是"这个插件不支持"。

**参数存 `SharedPreferences`，按包名分键。**
这里有个原则性区别要讲清楚：
- `UiSchema` 里的值 —— **插件自己的配置**，宿主绝不持久化（存了必然出现两边不一致）
- `PreviewParams` —— **宿主的调用入参**（这次用什么文本、哪段音频），插件只是被动接受

两者性质不同，所以一个存、一个不存，不矛盾。之前我可能把这个规则套太宽了。

**`cfg` / `timesteps` 故意不暴露。** 合理范围强依赖具体模型
（VoxCPM2 是 cfg≈2.0、steps 10–20），宿主猜不出默认值，猜错了比不填更糟。
这些该由插件在自己的界面里暴露。

## 4. 参考音频：两个 FD，两个主人

### 踩点
- SAF 选完文件后，**必须 `takePersistableUriPermission`**。
  不然 App 重启后这个 Uri 就读不了，用户看到的是"选过的东西又没了"，
  而且不会想到是授权过期。
- 打开后的 FD，**宿主那份要留到请求彻底结束**（成功/失败/取消）。
  插件是异步读的（它在自己的 worker 线程里 `fdopen` 复制），
  发完请求就 close 会让它读到 EBADF。
- Binder 传参时系统会 dup，所以插件拿到的是独立句柄。插件该关自己那份，
  宿主该关自己那份，互不影响。

### 另一个
`REQ_PREVIEW_REF = 0x9E01`，**故意避开 MainActivity 那一串 1001–1020**。
用重复的请求码，症状会是"选完音频，聊天里多出一张图" —— 能查一整天。

## 5. 结果只能听一次

### 现象
`playResult()` 固定写 `cache/plugin_preview.wav`，每试听一次覆盖一次。
生成的音频留不住。

### 做法
带时间戳写进 `getExternalFilesDir("tts")`：
`ponko-echo-1021-175423.wav`。
功能区加「保存」，走 MediaStore 写进系统「音乐/Ponko」——
Android 10 起不能随便往公共目录写文件，MediaStore 是官方通道，
而且存完立刻能在任何播放器里看到。

API 28 上没有 `RELATIVE_PATH`，退化成提示文件路径（文件本身在应用专属目录，
能长期留着，只是别的 App 找不到）。

## 6. 唤醒锁是一次性的

### 现象（预判到的）
`acquire(30 * 60 * 1000L)` 看着像"最多持 30 分钟"，实际是**到点自动释放**。
30 分钟对一次 TTS 够用，但下载 3.5 GB 模型时网速一慢就会掉锁，
然后进程被降级，下载卡死 —— 而且日志里什么都看不出来。

### 做法
工作期间每 10 分钟续一次：

```kotlin
private val wlRenew = object : Runnable {
    override fun run() {
        val wl = wakeLock ?: return
        if (!wl.isHeld) return
        // setReferenceCounted(false) 下再次 acquire 等于**重置超时**
        runCatching { wl.acquire(WAKELOCK_TIMEOUT_MS) }
        wlHandler.postDelayed(this, WAKELOCK_RENEW_MS)
    }
}
```

不用先 `release` 再 `acquire` —— 那中间有个被系统回收的窗口。
30 分钟上限保留，防止忘了 release 一直耗电。

## 7. 诊断信息不能只进 logcat

`ResultBundle.debugInfo` 以前宿主完全不用。**普通用户装不了 adb**，
所以"排查时看不到任何信息"和"这个功能没做"在用户眼里是一样的。

现在插件页底部有个折叠的「诊断信息」，显示 `debugInfo` + 最后一条错误的
码/名/`message`/`detail`，可长按复制。

### 一个实现细节
这块**必须先建成 `GONE` 再按需显示**，不能"有内容才创建"。
因为结果/错误回来时页面已经画完了：等下次进页面才出现，那时候用户
已经拿不到上下文（他刚看到的报错已经翻篇了）。

## 8. 别在别人的工作树里编代码

`Ponko-EX` 仓库现在挂着两条以上的线。这次要重编 Echo（在 `Ponko-EX_test`），
但工作树**正停在 `Ponko-EX_VoxCPM2`** —— 那条线明确不归这个对话管。

用 `git worktree add` 把测试线单独检出到别的目录去编，编完 `remove --force` + `prune`。

### 踩到的坑
```bash
git worktree add C:\PonkoEXTest Ponko-EX_test      # ✗
```
在 Git Bash 里这个路径被当成了**相对路径**，实际建在
`Desktop/Ponko-EX/PonkoEXTest` —— 在用户工作树里凭空多出一个未跟踪目录。

正确写法是正斜杠绝对路径：
```bash
git worktree add "C:/PonkoEXTest" Ponko-EX_test    # ✓
```

**教训：跨目录写东西一律用绝对正斜杠路径，并且建完立刻 `ls` 确认位置。**
这和之前"往工作区外写文件要用 PowerShell 并回读校验"是同一类问题。

## 9. 收尾：40 字上限是我加错的

### 现象
试听文本输入框限了 40 字，还挂了个 `InputFilter` 硬截断。

### 为什么加
想的是"手机上 RTF 10-30，40 字已经要几分钟，不设上限用户会粘一整篇文章然后以为卡死"。

### 为什么错
**因果反了。** 逻辑链是「这个插件很慢 → 所以 UI 要限长」，但：

1. **宿主不知道插件的 RTF。** 那个 10-30 是 VoxCPM2 的数字，不是所有插件的
2. **40 字成了全局上限**，Piper / Kokoro 这类轻量模型同样被捆住 —— 对它们纯属添乱
3. **UI 的问题不归推理管。** 用户愿意等多久是他自己的判断；真有必要限制，
   是插件回 `invalidRequest` 并说明原因，宿主照实转达
4. 硬截断还**静默丢内容** —— 粘 200 字只剩前 40 字，用户不知道

### 改成什么
- 删掉上限和 `InputFilter`，单行改多行
- 输入框下面一行实时估算：「约 9.0 秒语音 · 估算需 1.5 分钟 ~ 4.5 分钟（仅供参考）」
- 只**告知**，不**限制**

### 教训
这条能推广：**别用下游的性能约束去限制上游的输入**。
宿主是"呈现层"，它不该因为某个插件慢，就把这个慢变成所有插件的界面规则。
能做的是把信息摆出来（耗时估算），让用户自己决定。

顺带还有一个同源的错误一起清了：`advancedActivity`
（"插件自己画整个设置页"）**从来没有实现过** —— 只在两处注释里写着，像是存在。
文档承诺了不存在的东西，比不承诺更糟：插件作者会照着声明，然后发现毫无反应。
已删掉，并在 `UiSchema.kt` 里如实写明"现在只能决定有哪些项和顺序，纵向排列"。
