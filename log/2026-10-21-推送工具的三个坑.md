# 2026-10-21 · 推送工具的三个坑

本机 `git push` 不通（exit 128，无输出），只能走 GitHub 的 Git Data API。
`tools/push-via-api.py` 就是为这个写的。写它的过程中撞了三件事，
其中第 2 条**会静默产生坏数据**，最值得记。

---

## 1. 空仓库上 Git Data API 全部 409

### 现象
仓库刚建、还是空的，`POST /git/blobs` 返回：
```
409 Conflict  {"message":"Git Repository is empty"}
```
`POST /git/trees`、`GET /git/ref/heads/main` 也一样。

### 原因
GitHub 要求仓库里**先有一个提交**，Git Data API 才开始工作。
只有 Contents API（`PUT /repos/{r}/contents/{path}`）能在空仓库上用。

### 做法
先 `PUT` 一个占位文件造出初始提交，拿到它的 sha 当 parent，
之后正常流程接上去 —— 因为本地没有这个占位文件，它会被当成
「远端多出来的」自动删掉。最终 HEAD 内容干净，只是历史里多一条 bootstrap。

### 坑中坑
Contents API 只会往**默认分支**上提交。给第二个分支做 bootstrap 时，
它会把提交加到 `main` 顶上，然后 `PATCH refs/heads/<另一个分支>` 报
`422 Reference does not exist` —— 而 `main` 已经被污染了。

正确做法：**bootstrap 只在仓库真正为空时做一次**。
后面的分支从上一分支的远端 HEAD 派生，用 `POST /git/refs` 建 ref：

```
parent = 上一分支的远端 HEAD
POST /git/refs  {ref: refs/heads/Ponko-EX_test, sha: parent}
```

## 2. `git ls-tree` 会把中文路径转义，直接当路径用 = 静默坏数据

### 现象
推完了，脚本报"成功"，文件数也对。但 GitHub 上：

- 顶层多出一个叫 **`"log`** 的目录（名字里带一个字面双引号）
- 真正的 `log/` 里只剩 `README.md`
- 那个中文名的文件躺在 `"log/2026-10-21-\344\273\216\351\233\266....md`

### 原因
`git ls-tree` 对非 ASCII 路径默认**加引号并转义成八进制**：

```
100644 blob c116ac98...	"log/2026-10-21-\344\273\216\351\233\266\346\220\255..."
```

我把这一整串（含引号和反斜杠）当成路径传给了 API。远端老老实实建了一个
名字里带反斜杠和数字的文件 —— **谁都没报错**。

### 做法
用 `-z`：NUL 分隔，不加引号、不转义，拿到的是原始 UTF-8 字节。

```python
out = git("ls-tree", "-r", "-z", rev, binary=True)
for rec in out.split(b"\0"):
    meta, path = rec.split(b"\t", 1)
    items[path.decode("utf-8")] = ...
```

### 为什么这条最值得记
它不是崩溃，是**看起来成功**。如果不是我顺手比对了 tree sha，
这个仓库就会带着一个错名字的目录一直放在那儿，而且 clone 下来
`log/` 里少一个文件也不会有人立刻发现。

**验收手段**：比 `git rev-parse <branch>^{tree}` 与本端 commit 的 tree sha。
相等 = 内容完全一致（tree 是内容哈希，路径和 mode 都算在内）。
这一步现在应该固定做。

## 3. 错误响应体也是 gzip 的

### 现象
报错时打印出来是一堆乱码：
```
!! HTTP 404 %�1�0F� ����S��P�Zi�Q�{B�K����>��,W��M}lt�M�w�h:~
```
完全看不出哪里错了。

### 原因
请求头带了 `Accept-Encoding: gzip`（这是为了绕开本机链路对大响应的截断，
见工作区记忆里的另一条），**错误响应也会被压缩**。我的 `except HTTPError`
分支直接 `e.read().decode()` 就打印了。

### 做法
在错误分支里也先判断 `Content-Encoding` 再解压：

```python
raw = e.read()
if (e.headers.get("Content-Encoding") or "").lower() == "gzip":
    try: raw = gzip.decompress(raw)
    except Exception: pass
txt = raw.decode("utf-8", "replace")
```

## 顺带：干跑模式不能碰远端

第一版干跑（不带 `--apply`）只跳过写操作，读操作照做 —— 结果第二个提交
要读「parent 的 tree」，而 parent 在远端还不存在，直接 404 崩掉。

干跑就该**完全不发请求**（除了查仓库是否存在）。它要回答的是
"会推哪些东西"，不是"远端现在什么样"。

## 现在这套流程

```bash
python tools/push-via-api.py                      # 干跑，列出每个提交带多少文件
python tools/push-via-api.py --apply              # 推
python tools/push-via-api.py --apply --create-repo  # 仓库不存在时新建
```

推完必须核对两件事：

1. `git rev-parse <branch>^{tree}` == 远端 commit 的 `tree.sha`
2. 顶层条目里没有奇怪名字（比如带引号、带反斜杠的）

两个都对，才算真推成功了。
