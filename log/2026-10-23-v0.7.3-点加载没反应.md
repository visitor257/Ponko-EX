# v0.7.3：点「加载模型」没反应

## 现象

宿主升到 v12.1 后点「加载模型」，界面**一点变化都没有**：状态行还是"未加载"、
按钮还是亮的、日志框里也没有新行。像按钮根本没接上。

## 原因

`loadEngineBlocking()` 开头有个幂等早退：

```kotlin
if (VoxCpm2Bridge.nativeIsReady()) {
    return EngineInfo(sampleRate, 1, loadedBytes, SystemClock.elapsedRealtime() - t0)
}
```

它只 return，**不碰 Kotlin 侧的任何字段**。而 `nativeReady` 和原生状态是可能不一致的：

- `closeEngineBlocking()` 里 `nativeFree()` 被 `runCatching` 包着 —— 抛了异常也照样
  往下走 `nativeReady = false`。于是 Kotlin 认为已释放，原生其实还活着
- 用户释放后立刻又点加载，原生还没 free 完
- 宿主断开重连换了 service 实例：原生库是**进程级**的，初始化状态还在，
  而 Kotlin 字段从 false 重新开始

一旦进了这个状态，之后每次点加载都走到早退、直接 return：`nativeReady` 永远不翻成
true → 界面永远写"未加载 · 点加载"、按钮永远可点、日志里一行都没有
（`loadFromUi` 当时是 `if (nativeReady || engineLoading) return`，静默丢弃）。
**"点了没反应"就是这条链**，而且它不会自愈，只能重启进程。

## 做法

三处：

1. **早退必须补同步**。`nativeIsReady()` 为真而 `nativeReady` 是 false 时，把
   `sampleRate` / `loadedBytes` / `loadedSourceKey` / `loadedThreads` 一起补齐，
   `nativeReady = true`，写一行日志，再 `notifySchemaChanged()` 让按钮翻转。
   `loadFromUi` 里那句 `renderedByLoad = nativeReady` 因此自然变 true，不会多画一次。
2. **不再静默 return**。`loadFromUi` 被"已就绪"或"上一次还在跑"挡住时各写一行日志。
   下次再遇到，日志能直接说出是哪条挡的，不用再靠猜。
3. **`engineUnloading` 从布尔改成时间戳**。它原来只靠延迟 600 ms 的那个线程复位，
   线程没跑成就永久为 true，「加载模型」永久灰着，而且 `help` 是空的（因为
   `readySet != null`），用户看不到任何原因。改成 `unloadingSince` +
   `UNLOAD_GRACE_MS = 5s`，超时自己失效 —— 宁可让用户提前点一下
   （`nativeFree` 是幂等的），也不要让按钮永久像死了一样。

顺手把 `createManifest().versionName` 从写死的 `"0.5.0"` 改成 `0.7.3`：
插件卡片上那个版本号一直没跟着 build.gradle.kts 动，是假的。

## 教训

**"幂等早退"不能只退，要把状态对齐。** 早退的前提是"两边本来就一致"，
而它存在的理由恰恰是"两边可能不一致" —— 这两句话不能同时成立。
要么退之前先同步，要么就别退。
