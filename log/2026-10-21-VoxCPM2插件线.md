# 2026-10-21 · VoxCPM2 插件线（Ponko-EX_VoxCPM2）

第一条**真插件**线。Echo 那条只验链路，这条要真的出声。

分支从 `main` 派生，只 include `:plugins:voxcpm2`。

---

## 接口是照着 VoxCPM2 设计的，省了一大截

打开 SDK 源码才发现：`SynthesisRequest` 里的 `mode` / `referenceAudio` /
`referenceTranscript` / `voiceDescription` / `cfg` / `timesteps` / `seed` 全都是
为这个模型准备的（注释里直接写了 `voxcpm2_jni.cpp:211`）。

所以插件侧不用做任何"翻译层"，`req` 的字段一一对应原生 `nativeGenerate` 的入参。
**唯一要自己处理的**是 `voiceDescription` —— 它不是独立参数，而是要拼成文本前缀
`"(描述)正文"`，并且如果宿主传的正文已经以 `(` 开头就不能再拼（否则双前缀）。

## 坑 1：JNI 符号名和包名绑死了

原生库里的符号是**编译期写死**的：

```
Java_com_voxcpm_test_VoxCpm2Bridge_nativeInit
```

插件里的类在 `com.litertchat.plugin.voxcpm2`，名字对不上，`System.loadLibrary`
之后调用会直接 `UnsatisfiedLinkError`。

三条路：

| 做法 | 代价 |
|---|---|
| 插件里硬写 `package com.voxcpm.test` | 能用，但半年后没人看得懂为什么 |
| 复制一份 343 行的 cpp 改名字 | 两份副本必然漂移 |
| **同一份源，编译期换前缀** | 多编一个 cpp + 链接，几十秒 |

选了第三条。CMake 里加 `target_compile_definitions(... PONKO_PLUGIN)`，
源码里：

```cpp
#ifdef PONKO_PLUGIN
#define JNI_NAME(fn) Java_com_litertchat_plugin_voxcpm2_VoxCpm2Bridge_##fn
#else
#define JNI_NAME(fn) Java_com_voxcpm_test_VoxCpm2Bridge_##fn
#endif
```

### 这里踩了一个宏的坑，值得记住

第一版写的是"标准两级拼接"：

```cpp
#define JNI_NAME2(cls, fn) Java_##cls##_##fn
#define JNI_NAME(fn)       JNI_NAME2(JNI_CLASS, fn)
```

编出来 `nm` 一看全是 `Java_JNI_CLASS_nativeInit` —— **一个字面量 JNI_CLASS**。

原因：`JNI_NAME2` 里 `cls` 紧挨着 `##`，宏展开时**参数不做预展开**。
`JNI_NAME` 那层也救不了，因为它在 rescan 时把 `JNI_CLASS` 当普通实参交给了
`JNI_NAME2`，而 `JNI_NAME2` 因为 `##` 拒绝展开它。经典的"两级拼接要靠外层
先展开"的规则，在这里正好被 `##` 卡死。

**判据**：`nm -D --defined-only <so> | grep Java` 必须能数出 10 个自己的符号。
数不出来就是符号名不对，别去猜别的地方。

## 坑 2：下载不能占着 worker

基类的 `onActionInvoked` 是在**单线程 worker** 上跑的（`setSetting` 也是）。
第一版把 3.3 GB 的下载直接写在里面，结果是：下载跑着的时候，
「取消下载」这个 action 排在它后面，**永远轮不到** —— 用户点了没反应，
只能强杀插件进程。

改法：下载另开一条 `Thread`，`onActionInvoked` 立刻返回；
取消靠一个 `AtomicBoolean`，下载循环每 256 KB 检查一次。

进度回调约 400 ms 一次，直接 `notifySchemaChanged()` 会把整页刷崩，
所以外面套了一层 700 ms 节流（手册里写的是"别高频调"，这是具体做法）。

## 坑 3：许可上的实质缺口

`llama.cpp-omni` / ggml 是 **MIT**，静态链接进 `libvoxcpm2jni.so` 之后，
**分发 APK 就得随包附版权声明和许可全文**。原来的测试 APK 里一个字都没有 ——
自己装没事，发给别人就违约了。

这条线补了三处：

1. 仓库根 `LICENSE`（MIT，本来就该有）
2. `plugins/voxcpm2/NOTICE.md` —— 引擎 MIT 全文 + 权重 Apache-2.0 归属 + 修改声明
3. 插件界面里一个 `INFO` 项 —— 用户看得见的那一份（很多人只会看到界面）

顺手把下载源也分开了：默认走魔搭 `DennisHuang/VoxCPM2-GGUF`（仓库标了
apache-2.0），省 0.7 GB 的 `zerg13` 那个**没填 license 字段**，所以不做默认。

## 坑 4：`useLegacyPackaging` 又是必须的

宿主那边踩过一次（不设的话 AGP 给未压缩 `.so` 补 4K 对齐零填充，包凭空大 5.7 MB）。
插件同样要写。写了之后 5.7 MB 的 `.so` 是**压缩存储**的，APK 只有 4.6 MB。

## 产物

```
plugins/voxcpm2/build/outputs/apk/release/Ponko-EX_VoxCPM2_release.apk
  4.6 MB（4,621,699 B）· 签名 v1+v2+v3 全 true · sha256 6c7370fd…d15b0
  包名 com.litertchat.plugin.voxcpm2 · arm64-v8a · minSdk 28
  内含 lib/arm64-v8a/libvoxcpm2jni.so（5,772,392 B，10 个 JNI 符号）
```

宿主的 signature 权限要求插件**必须用宿主那把密钥签名**，
所以用的是 `LiteRT-Chat/tools/sign-apk.ps1`（读宿主的 `keystore.properties`）。
换个宿主编译（比如 hw 线）就要换密钥重签，否则 bind 直接 SecurityException。

出包命令（两条，第二条直接产出正式文件名）：

```
tools\build.bat :plugins:voxcpm2:assembleRelease
powershell -ExecutionPolicy Bypass -File LiteRT-Chat\tools\sign-apk.ps1 ^
  -Apk plugins\voxcpm2\build\outputs\apk\release\voxcpm2-release-unsigned.apk ^
  -Out plugins\voxcpm2\build\outputs\apk\release\Ponko-EX_VoxCPM2_release.apk
```
