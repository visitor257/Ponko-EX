# v0.5.0：三页（模型 / 参数 / 结果）+ 本地导入

> 2026-10-22 晚。跟着宿主 **SDK v6**（`23f3b08` 的 `MODEL_SLOT` / `importModel`）
> 和 **可滑动标签页**（`3239bdb` 的 ViewPager）重做界面。
> 版本 `0.4.0 → 0.5.0`，versionCode `9 → 10`，报 `apiVersion = 6`。

## 用户给的目标长什么样

```
三页（可左右滑）：模型 // 参数 // 结果

模型页：已导入模型 · 加载/卸载 · 选择模型(本地导入) · 下载(类型/Q8·Q4、hf/hf-mirror、进度) · 删除
参数页：模式(TTS/克隆/极致克隆) · 目标文本 · 开始推理 · 进度+种子 · 克隆音频/逐字稿/种子/cfg/扩散/线程 · 诊断 · 日志
结果页：上次结果(种子/cfg/扩散/文本/播放/保存) · 历史(最多5条，每条同样内容)
```

下面按"能做 / 不能做"逐条对账。

## 能做的（都做了）

**三页 + 左右滑**：`TABS_START` 是最外层、也不在任何 GROUP 里，所以宿主把它渲染成
ViewPager（`3239bdb` 的条件：`depth == 0 && target.size == 1`）。切页是纯 visibility，
输入框内容和滚动位置都留着。

**模型页**
- `MODEL_SLOT`（v6）给「已导入 / 导入 / 清除」—— 一个槽位一个文件。
  为什么是两个槽位而不是一个"选择模型"：SAF 一次只能选一个文件，而 VoxCPM2 是
  两份 GGUF。硬凑成一个按钮只能"选完再问你选另一份"。
- 加载 / 释放：插件自己调 `loadEngineBlocking` / `closeEngineBlocking`
  （引擎本来就归它），宿主功能区那对按钮落到同两个方法，状态是同一份。
- 下载改成**版本 × 镜像**两个维度：版本（标准 Q8 / 精简 Q4）× 镜像
  （hf-mirror / HF / 魔搭），**只列真实存在的组合**。
- 删除：`dl_delete` 删下载的；导入的那份走槽位自带的「清除」。

**参数页**：cfg / 扩散步数 / 语音设计描述 / **种子** / **线程**（都是插件真能影响的），
推理进度条（`notifyUiPatch` 原地补丁），上次用的参数与耗时，诊断分组，日志 + 清空。

**结果页**：上次的种子 / 参数 / 目标文本 / 播放条 / 耗时；历史最多 5 条（只存内存）。

## 做不了的（三处，都给宿主写了报告）

报告：`log/2026-10-22-报给宿主-插件页发起合成与历史播放.md`

1. **「开始推理」按钮**
   `PluginConnection.matchesActive()` 是 `activeRequestId ?: return false` ——
   空闲时插件推 `onResult` 会被**静默丢弃**；而 `IPonkoCallback` 没有音频下行通道。
   所以插件侧按钮无法让宿主拿到音频、也就没有播放和保存。
   → 参数页只说明"入口是顶部「合成语音」"。宿主若加一个
   `oneway void requestSynthesis()`，这条就能通。

2. **历史逐条的播放 / 保存**
   宿主只有一份 `lastAudioFile`、一个 `MediaPlayer`、一个「保存」动作，
   所有 `UiType.AUDIO` 播放条共用同一个 `AudioHost`。五条历史各配一个播放按钮，
   按哪条都放最近那份 —— 那是假的，所以不做。

3. **诊断信息默认收起**
   `buildGroup()` 里 `groupOpen[key] ?: true`，插件无法声明"初始收起"。
   现状：默认展开，让用户自己点一下。建议宿主借 `GROUP_START.value` 约定一个开关。

**另外两处按"不做假控件"原则主动放弃**：模式 / 目标文本 / 参考音频 / 逐字稿。
它们属于宿主 `PreviewParams`，宿主才是发起方；插件页摆一份改了不生效的文本框，
比不摆更糟。参数页用一行 INFO 说明去哪儿改。

## 一个查证过的细节：hf 和 hf-mirror 不是所有版本都有

用户要求「从 hf 下载 / 从 hf-mirror 下载」。实测（HEAD + hf-mirror 的 API）：

| 地址 | 结果 |
|---|---|
| `hf-mirror.com/tc-mb/MiniCPM-V-Apps-gguf/.../Q4_K_M.gguf` | 200，1 002 374 880 B |
| `hf-mirror.com/tc-mb/MiniCPM-V-Apps-gguf/.../Acoustic-F16.gguf` | 200，1 825 096 352 B |
| `huggingface.co/...`（同一路径） | 连接超时（本机网络，符合预期） |
| `hf-mirror.com/DennisHuang/VoxCPM2-GGUF/.../Q8_0.gguf` | **404** |
| `hf-mirror.com/api/models/tc-mb/MiniCPM-V-Apps-gguf` | 200，仓库真实存在 |

hf-mirror 只代理 HF 上真有的仓库，所以 **标准 Q8 那个仓库在 HF 上不存在**，
标准版只能走魔搭。界面上因此按版本过滤镜像 —— 画一个点下去 404 的按钮比不画更糟。

**顺带回答了"独立测试版用的是哪个"**：`voxcpm2_android` 用的是
`VoxCPM2-BaseLM-Q4_K_M.gguf` + `VoxCPM2-Acoustic-F16.gguf`，也就是**精简 Q4**
（2.83 GB），源是 `zerg13/MiniCPM-V-Apps-gguf`（魔搭）和 `tc-mb/...`（hf-mirror）。

## 实现上的几个决定

- **本地导入先写 `.part` 再原子改名**。复制 1.7 GB 要几十秒，中途被清后台会留下
  半截文件 —— 那比没有更糟：`ready()` 会把它当"已导入"，native 报一个看不懂的
  GGUF 错误。
- **导入优先于下载**：用户特意从本地导进来，说明他要的就是那个文件。
  `ModelStore.ready()` 的顺序是 导入 → 任一已下完整的版本。
- **种子 / 线程是"填了才压过宿主"**：空 = 跟随宿主（种子随机、线程跟 Ponko 顶部），
  填了 = 用它。这是这两项存在的意义；反过来（宿主永远赢）就等于假控件。
- **推理进度是估计值**：原生只给 `nativeAudioSeconds()`，没有总步数，
  总长按字数估（0.22 秒/字）。所以最后可能停在 90% 再跳满，help 里写明了。
- **加载按钮另开线程**：基类 worker 是单线程的，加载 10~30 秒会把
  「释放模型」「取消下载」全堵在队列里。
- **镜像按钮用前缀匹配**（`dl_` + 镜像 key），以后加镜像只改 `ModelStore` 一行。
