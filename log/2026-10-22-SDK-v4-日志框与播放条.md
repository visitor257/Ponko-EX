# 跟上宿主 SDK v4：日志框、播放条、原地补丁（插件 v0.3.0）

> 2026-10-22。宿主那边两个提交把 SDK 推到 v4，这条线跟着改到 v0.3.0。
> 宿主侧代码不在本仓库，这里的记录只写"插件这边用了什么、为什么这样用"。

## 宿主这次给了什么

宿主仓库（`LiteRT-Chat`）两个提交：

| 提交 | 内容 |
|---|---|
| `82d6894` | **SDK v4**：`UiType.LOG` / `IMAGE` / `AUDIO`（12/13/14），`IPonkoCallback` 末尾追加 `onImage()` / `onUiPatch()`，`API_VERSION = 4` |
| `a719b75` | 补出口：`PonkoPluginService` 原来只有 `notifySchemaChanged()`，`callback` 是 private，**插件根本调不到这两个新回调**。补了 `notifyUiPatch(key, value, append)` / `notifyImage(fd\|file, w, h, mime)` |

三个新类型和前面 12 种有本质区别：**它们不是配置项，是"过程和产物"**。
不参与 `setSetting`（用户改不了），内容走另外两个回调。

对我们有用的只有两个：

- `LOG` —— 只读日志框，固定 160 dp 高、内部滚动、长按可复制
- `AUDIO` —— 播放条（播放/暂停 + 可拖进度 + 「0:03 / 0:12」）

`IMAGE` 用不上：这个插件产出的是音频。

## 为什么 LOG 这一项值得改

以前日志是「可折叠分组 + 一段 `INFO` 快照」，`INFO` 是**一次性**的，
要更新只能 `notifySchemaChanged()` —— 那是宿主的 `removeAllViews()` **整页重建**。
后果很具体：

- 日志每来一行，用户滚到一半的位置被拉回顶部
- 正在填的「语音设计描述」（`TEXTAREA`）失焦、内容被覆盖
- 三十来个控件全部重建，下载时那一秒一次的重建肉眼可见地卡

所以 v0.2.x 干脆**攒着**：环形缓冲 120 行，只显示最后 24 行，靠调用方在粗粒度节点
（开始/结束/失败）自己决定什么时候重画。代价是推理过程中间那几十秒日志是静止的。

换 `LOG` 之后就没有这个取舍了：新行单独推给那一个 `TextView`，别的控件一动不动。

## 三个实现选择（都不显然）

### 1. 推整段快照，不是"只推新行"

补丁是 `notifyUiPatch(key, text, append = false)` —— **替换**，每次把 120 行全发过去
（约 8 KB），不是 `append = true` 只发新的那一行。

两个理由：

- 缓冲满 120 行会丢最老的。只追加的话，界面上的行数会无限涨，越用越卡
- 整段替换是**幂等**的：不需要维护"界面上已经有哪几行"的游标。页面重建和补丁
  交错时（重建发生在宿主主线程，补丁从插件的 worker 线程来），游标一定会算错，
  表现是漏行或重复行 —— 而且是偶发的，很难查

8 KB / 250 ms 对 Binder 配额没有压力（单次事务上限 1 MB）。

### 2. 被节流掉的那一次要「补推」，不能直接丢

`onUiPatch` 是 `oneway`、**没有背压**，宿主处理慢于插件时消息会在它那边排队，
所以必须节流。但直接丢掉被节流的那次有个坑：

> 最后一行日志（比如「下载完成」）正好落在节流窗口里，之后再也不会有新行 →
> 这一行**永远不出现**，直到用户退出再进来一次。

所以节流时挂一个延迟任务补推最后的状态：

```kotlin
if (!force && now - lastLogPushAt < LOG_PUSH_INTERVAL_MS) {
    mainHandler.removeCallbacks(flushLogTask)
    mainHandler.postDelayed(flushLogTask, LOG_PUSH_INTERVAL_MS)
    return
}
```

用 `Handler(Looper.getMainLooper())` 而不是自己起线程：服务进程本来就有主线程，
一次性延时任务没必要再弄一个。

### 3. 下载进度也改走补丁，而且**不再周期性整页重建**

原来下载回调里是 `notifyThrottled()`（1 秒一次整页重建）。下载回调一秒来几十次，
1 秒重建一次已经是妥协了，但那 1 秒一次的重建照样会冲掉日志滚动位置和输入框。

现在推两个 key：

- `dl_progress` —— `PROGRESS`，值 0–100，宿主会同时改进度条和百分比文字
- `file_<文件名>` —— 当前那个文件的 `STATUS` 行（「下载中 · 1.2 GB / 2.0 GB」）

整页重建只在**一个文件下完**的时候来一次（那一行要从"下载中"变成"已就绪"，
补丁只能改值、改不了行的存在与否）。

`dl_progress` / `file_` 这两个前缀写成了常量 `KEY_DL_PROGRESS` / `KEY_FILE_PREFIX`，
schema 和补丁共用 —— 宿主对不上 key 是**静默忽略**，不会去猜你大概想改哪个，
所以这种字面量绝不能在两处各写一遍。

## 播放条放哪儿

放在「运行状态」下面单独一个 `试听` 分区，排在「1 · 权重」之前。

它播的是**宿主手里那份产物**（最近一次「合成语音」的结果）。插件不传路径、
也传不了 —— 插件在另一个进程，自己播的话退出这个页面声音还在响，宿主停不掉
（管不到别人的 `MediaPlayer`），而且音频焦点、来电打断都是宿主已经有的实现。

和上面那个「播放」按钮**是同一个播放器**，区别只在于这里能看时间、能拖进度。
一两分钟的长音频想听某一句，按钮无能为力。

## ⚠ 兼容性：这次是硬门槛，不是降级

插件报的 `apiVersion` 来自 SDK 的 `PluginConst.API_VERSION`，编进去就是 4。
宿主那边 `PluginConnection` 是这么判的：

```kotlin
if (api !in PluginConst.API_MIN_SUPPORTED..PluginConst.API_MAX_SUPPORTED) { 拒绝绑定 }
```

所以 **v4 插件装到 `API_MAX_SUPPORTED = 3` 的老宿主上 → 直接拒绝**，
界面只会写「插件 SDK v4 不兼容」，连降级成纯文本都没有机会。

这不是我们可以绕过的：`UiItem.type = LOG / AUDIO` 老宿主不认识，本来会走
`unknownItem()` 降级成文字块（这条路径是好的），但版本闸门在**渲染之前**就把
插件挡掉了。

结论：**宿主必须先更新**。宿主那边的版本闸门是否要改成"只拒绝更低的、接受更高的"，
属于宿主侧的设计决定 —— 已在报告里提过（见 `2026-10-22-报给宿主-引擎生命周期与试听语义.md` 末尾）。

另一个必须做的动作：**改 AIDL / 基类之后要重新发布 SDK AAR**。

```
cd C:\PonkoBuild
tools\build-android.bat :ponko-plugin-sdk:publishReleasePublicationToLocalRepoRepository
```

版本号还是 `1.0.0`，所以插件构建必须带 `--refresh-dependencies`，
否则 Gradle 认为依赖没变、继续用缓存里的旧 AAR —— 症状是
`Unresolved reference: notifyUiPatch`，看着像 SDK 写错了。

发布后核对方式（`assembleRelease` **不会**重新打包 AAR，抽 `build/outputs/aar/*.aar`
会拿到旧包、误报 MISSING）：

```
ls -l /c/ponko-maven/com/litertchat/ponko/plugin-sdk/1.0.0/plugin-sdk-1.0.0.aar   # 94911 → 96869
python -c "...读 classes.jar 里的 PonkoPluginService.class，找 notifyUiPatch / notifyImage..."
```

## 顺带：宿主的按钮行还是没改

`PluginUiPage.kt` 里那五个功能按钮仍然是 `WRAP_CONTENT` + 左右各 16 dp padding +
8 dp 间距。360 dp 屏可用宽度 328 dp，这五个按钮字号 13 sp 时总需求约 374 dp，
**「保存」被裁掉约 46 dp**。这次的宿主更新没碰这块。

改法还是那份报告里的：`LayoutParams(0, WRAP_CONTENT, 1f)` + padding 16→4 dp +
间距 8→6 dp + textSize 13→11 sp + `maxLines = 2`，**一组一起改**，只加 `weight`
会更糟（每个按钮 59 dp，文字区 27 dp，「加载模型」折成四行）。
字体那行必须改在 `applyActionStyle()` 里面 —— `setActionEnabled()` 每次都会重调它，
在外面设会被 13f 冲掉。

插件这边不需要配合：4 个字的标签 11 sp 正好放下，「模型」这个词是覆写的全部理由，
不该为了排版删掉。
