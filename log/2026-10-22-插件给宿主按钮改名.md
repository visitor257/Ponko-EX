# 让插件给宿主的按钮改名（2026-10-22）

## 起因

插件页顶部那排按钮（加载引擎 / 试听 / 播放 / 停止 / 保存）是**宿主画的**，
文字也写死在宿主里。问题是同一件事在不同插件里叫法确实不一样：

| 插件 | 「加载引擎」对它意味着什么 |
|---|---|
| VoxCPM2（3.5 GB 本地模型） | 加载 3.5 GB，几十秒，占内存 |
| Piper / Kokoro（轻模型） | 几百毫秒的事，而且体积小到用户不在意 |
| 走网络 API 的 TTS | **根本没有模型**，应该是「连接服务」 |
| Echo（测试插件） | 加载一个假引擎，「试听」试的也不是语音 |

用户看到「加载引擎」这四个字，对第一种能理解，对第三种就是错的。
**按钮是宿主的界面，但按钮的含义只有插件知道。**

## 第一个决定：不动 `PluginManifest`

最自然的写法是给 `PluginManifest` 加一个 `actionLabels: List<String>` 字段。
**没这么做**，原因很具体：

`PluginManifest` 是 `@Parcelize` 生成的，`CREATOR` 按固定顺序读字段。
老插件用旧 SDK 编译，它写出来的 Parcel **少一个字段**；宿主用新 SDK 去读，
会读到 Parcel 边界之外 → **抛异常**。

也就是说，往 Parcelable 里加字段 = **所有插件必须同时重编**，
否则连都连不上。而「老插件继续能用」正是 `API_VERSION` 机制要保住的东西。

想绕开这个，就得手写 `CREATOR`，在里面按 `apiVersion` 判断该不该读新字段：

```kotlin
constructor(p: Parcel) {
    apiVersion = p.readInt()
    ...老字段...
    actionLabels = if (apiVersion >= 3) p.createStringArrayList() ?: emptyList() else emptyList()
}
```

可行，但比加一个方法复杂，而且**以后每加一个字段都要再想一遍这件事**。

所以改成：**AIDL 末尾加一个方法**。

```aidl
List<String> getActionLabels();
```

宿主按 `pluginApi >= API_WITH_ACTION_LABELS` 决定要不要调。
老插件的 Binder 只认识事务码 1..11，宿主不去发第 12 号，两边都安全。

> 这次没有踩「AIDL 新方法插在中间」的坑，因为之前的记录里已经写了：
> 事务码按**声明顺序**分配，插在中间会让后面所有方法的码整体后移，
> 老插件收到对不上的码会**执行错的方法**，比报错更糟。

## 第二个决定：默认文案不放 SDK

第一版我把宿主默认文案写成了 `ActionLabel.defaultFor(key)`，放在 SDK 里。
写完就发现不对：**SDK 会被打进每个插件 APK**。

后果：
- 每个插件都揣一份别的 App 的中文字符串，全世界只有 Ponko 用得到
- 以后做多语言要改两处（SDK 一份、宿主一份）
- 改完还得让所有插件重编才生效 —— 这是最要命的

挪到宿主 `app/.../plugin/ActionLabels.kt`。SDK 里只留 **key + 解析逻辑 + 长度上限**，
这些是插件真正需要知道的；默认叫什么名字是宿主的家务事。

验证方法：编完插件后 `grep` 它的 dex，确认 `卸载引擎` / `重新合成` 一个都没有。

## 为什么只能改文字

位置、个数、颜色、可点状态、点击行为，**全归宿主**。插件只能给自己那一格换个说法。

这不是限制得不够大方，而是必需的：如果插件能把「停止」改叫「保存」，
用户会按字面理解去点，然后丢掉正在生成的那段音频。

名字可以商量，行为不能外包。

这条**代码拦不住**（宿主没法判断一个词是不是"听起来危险"），只能写进文档：

> 别把破坏性动作改得听起来无害。

## 容错的三个层次

| 谁 | 拦什么 |
|---|---|
| 插件基类 `getActionLabels()` | 未知 key、空值、超长 → 记日志 + 丢弃该项（插件作者自己能看见） |
| SDK `ActionLabel.parse()` | 同上，再拦一遍（防插件绕过基类自己实现 AIDL） |
| 宿主 `PluginConnection` | `getActionLabels()` 抛异常 → 全部退回默认，**不影响连接** |

两边都拦一次的成本几乎为零，而且各自留下自己的日志。

**超长为什么是丢弃而不是截断**：截出来是「加载模型 3.5…」，
比原来那句完整的默认文案更难懂。宁可退回默认。

**为什么失败不影响连接**：文案是锦上添花。插件写错一个 key 就不让用户用这个插件，
是把装饰性错误当成了致命错误 —— 跟之前「引擎状态判断错」那类 bug 是同一个模式。

## 顺带改掉的两处不一致

按钮能改名之后，**提示文字里引用按钮名**的地方就自相矛盾了：

| 位置 | 原来 | 现在 |
|---|---|---|
| 开始生成时 | 「…可随时点**停止**」 | 用 `session.actionLabel(pkg, STOP)` |
| 播放完毕 | 「点**保存**可存进音乐库」 | 同理 |
| 加载/卸载中 | 「正在**卸载引擎**…」 | 用对应按钮的名字 |

第三处尤其明显：插件把按钮叫「释放模型」时，下面提示说"正在卸载引擎"，
用户会以为是两件事同时在发生。

## Echo 的示范

只改两个，剩下的故意不写：

```kotlin
override fun buildActionLabels(): Map<String, String> = mapOf(
    ActionLabel.PREVIEW to "跑一次测试",
    ActionLabel.PREVIEW_AGAIN to "再跑一次",
)
```

这样同一行按钮里**两种来源同时存在**（前两个是插件的字，后面几个是宿主的默认），
一次就能看到"覆盖生效"和"没覆盖仍然用默认"两件事都成立 ——
比单独测一种情况更省事。

Echo 改名的理由也是真的：它不合成语音，只有一段琶音，叫「试听」会让用户以为在试音色。

## 版本

`API_VERSION` 2 → 3，`API_MAX_SUPPORTED` 2 → 3，`API_MIN_SUPPORTED` 保持 1。
全是扩展，没有破坏性改动。
