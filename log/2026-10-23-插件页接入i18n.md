# 插件页接上 i18n：宿主自己按语言走，插件提供自己的文案

起因是一个问题："插件能不能跟系统语言走，同时能设置默认语言？"

结论是**能，而且不用任何新接口** —— 但查的过程中发现宿主这边有个真缺口：
插件页是全 App 唯一没接 i18n 的地方。

---

## 一、插件侧：本来就是 Android 原生能力

插件是独立进程、读自己的资源，宿主只显示它给的字符串。所以"多语言"就是普通的
资源限定符，`values/` 就是"默认语言"：

```
系统语言 → 有 values-xx/ 就用 → 没有就落到 values/（兜底）
```

| 想要 | 怎么写 |
|---|---|
| 默认英文 | `values/` = 英文，其他放 `values-zh/` |
| 默认中文 | `values/` = 中文，`values-en/` 放英文 |
| 只有俄文 | `values/` = 俄文（**不能只建 `values-ru/`**） |

最后那条是唯一会崩的写法：只建 `values-ru/` 而不建 `values/`，中文手机上
`getString()` 抛 `ResourcesNotFoundException`，插件直接挂。

### 一个顺带发现的坑

`PluginException.notReady()` / `outOfMemory()` 的默认文案是**中文硬编码**，
而 **SDK 没有 `res/` 目录**，所以它们无法本地化。英文用户会看到中文报错，
除非插件显式传文案。这条以前没写在手册里。

---

## 二、宿主侧：插件页是全 App 唯一没做 i18n 的地方

查完才发现的事实：

| 文件 | `R.string` 引用 | 硬编码中文 |
|---|---|---|
| `MainActivity` | 333 | 12 |
| `DrawPage` | 215 | 3 |
| **插件模块（全部）** | **0** | **~250 处 UI 文案** |

`ActionLabels.kt` 的注释自己就写着"整个插件页都还没做 i18n…英文系统上这页本来就是中文"。
也就是说这个问题一直存在，只是没人把它当 bug 看。

实际表现：英文/日文系统下主界面是英文，进插件页突然全是中文，
而插件自己提供的名字（作者已经按语言分好资源了）又可能是英文 —— 中英混排。

### 做了什么

把约 250 处用户可见文案抽到 `strings.xml`（英文）+ `values-zh`（中文）：

| 范围 | 条数 |
|---|---|
| `ActionLabels`（宿主按钮默认文案） | 6 |
| `PluginPage`（卡片、状态行、参数区、播放条、弹窗、toast） | ~150 |
| `PluginUiPage`（返回、功能、诊断、模型槽位、开/关） | ~22 |
| `PluginConnection`（连接状态、bind 诊断、阶段名） | ~30 |
| `PluginDiscovery`（连不上时的逐条原因、探测详情） | ~23 |
| `PluginSession` | 5 |

**刻意不翻的**：
- `Log.*` 输出 —— 给开发者看的，保持单一语言反而便于 grep
- `PreviewParams.LEGACY_DEFAULT_TEXT` —— 不给人看，它是**比对旧 prefs 里那句示例文本**用的，
  翻了比对就失效

### 有 12 处不是"换字符串"，是重写结构

中文可以靠拼接：

```kotlin
"引擎已加载：${info.sampleRate} Hz" +
    "，占用 ${...} MB" +
    "，耗时 ${...} 秒"
```

英文语序不同，拆开的三段拼不回去。这类改成一个资源 + 位置参数：

```kotlin
if (info.modelBytes > 0) {
    getString(R.string.s_588, info.sampleRate, mb, sec)
} else {
    getString(R.string.s_589, info.sampleRate, sec)
}
```

带体积和不带体积拆成两条 —— 因为英文里从句位置不一样，靠拼接一定读着别扭。
同样处理了「插件 SDK vN（当前 vM）」和 `fmtDur` 的时长格式。

### 四个类都需要一个 `getString` 转发

`PluginPage` / `PluginUiPage` / `PluginConnection` / `PluginSession` 都是普通类，
不是 `Context`，没有继承来的 `getString`。各加一行转发到 `act.getString` /
`context.getString`（它们已带当前配置，含语言）。

**不能** 用 `createConfigurationContext` 那种固定了语言的 context 取文案。

## 三、过程里犯的两个错（都拦住了，但值得记）

### ① 脚本把注释里的中文也替换了

批量替换是按"带引号的完整字面量"匹配的，但注释里也有同样写法：

```kotlin
// 有查询却说"没有找到插件"会让人以为扫描坏了
```

被改成：

```kotlin
// 有查询却说getString(R.string.s_503)会让人以为扫描坏了
```

6 处，全部还原。**教训：批量替换前要排除注释行；替换后要 grep 注释区。**

### ② 两批脚本撞了 key

第二批用了 `s_582`–`s_587`，而第一批已经把这段用掉了（含 `复制` / `已复制`）。
结果 6 处长段落指向了无关的短词 —— 这个**编译能过**，只是显示错误，
比编译失败危险得多。

靠"中英两份 key 集合比对 + 重复检测"发现，改成 `s_614`–`s_619`。

**教训：分配 key 前先算出当前最大编号，而不是凭印象。** 我一开始以为上一批只用到
s_581，实际上 MISS 的项也占掉了编号。

## 验证

| 项 | 结果 |
|---|---|
| 编译 | BUILD SUCCESSFUL，零警告 |
| key 一致性 | 英 671 / 中 671，**无重复、无单边** |
| 打包 | `resources.arsc` 里中英两套值都在（抽查 `Uninstall`/`卸载`、`Synthesis settings`/`合成参数`） |
| 残留 | 插件模块只剩日志里的中文（约 25 处），无用户可见文案 |

## 一句话版

- **`values/` 就是"默认语言"**，不需要额外字段；但只建 `values-xx/` 会在别的语言上崩
- 文案必须**用到时现算**，别在 `onCreate` 里缓存 —— 切语言会重建 Activity
- **SDK 没有 `res/` 目录**，所以 SDK 里的默认文案（`PluginException`）天生无法本地化
- 拼接式模板在跨语言时要**重写成位置参数**，不能指望逐段翻译拼回去
- 批量替换中文 → 资源时，**注释行必须排除**，且 key 分配前先算最大编号
- 撞 key 不会编译失败，只会静默显示错误 —— 要用"两份 key 集合比对"兜住
