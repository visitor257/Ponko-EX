# v0.7.0 · 参数页三段接管，开始 / 停止共用一个槽位

> 宿主 v9 / v9.1 / v10（`48317d0`、`3cf7a80`、`dcd429c`）落地之后的第一版插件。
> 前一版 0.6.3 的界面之所以没变化，是因为那三条要求当时宿主一行都没改。

## 一、这一版解决的

| 要求 | 做法 |
|---|---|
| 开始按钮在目标文本**下面** | 参数页把宿主的 `params` 段先挂，`actions` 段后挂 |
| 进度条在**按钮下面** | `infer_progress` 紧跟在 `actions` 段之后，不再放在页底 |
| 参数页不要「加载模型」 | manifest 白名单 `ponko.actions = "reasoning,stop"` |
| 参数页不要「播放」 | 同上；播放入口在「结果」页（合成完自动跳过去） |
| 参数页不要「保存」 | 同上；结果页的播放条自带逐条「保存」（v7 起注入的 saver） |
| 开始 / 停止「视觉上是一个」 | 宿主把这两个叠进**同一个槽位**，按状态用 `INVISIBLE` 交替 |

关于最后一条：宿主实现的是 `sharedSlots = [REASONING, STOP]` ——
两个动作**都还在顶部**（没被插件搬走）时才合并成一格。
所以这一版刻意**没有**用 v9 的 `HostActionId` 去接管按钮位置：
一旦接管其中任何一个，它就离开顶部，配对失效，变回两个独立按钮。
「位置自由」和「交替显示」目前互斥，本插件选交替。

## 二、参数页现在的顺序

```
[宿主 params]  目标文本 / 模式 / 参考音频 / 逐字稿 / 种子 / 线程 / 后端
功能
[宿主 actions] [ 开始推理 ⇄ 停止 ]   ← 同一槽位，位置不动
[help 一行]     ← 宿主写的，插件去不掉（见下）
[状态提示]      正在合成… / 错误信息
[推理进度]
语音设计描述（默认）
CFG 引导强度
扩散步数
[宿主 diag]    诊断信息 ▸（默认收起）
插件内部状态 ▸
运行日志 ▸（含「清空日志」）
```

删掉的：`上次用的参数` / `上次耗时` 两行 —— 结果页有同样的数字，
参数页再来一份只是把页面拉长。

## 三、留给宿主的两处（都不影响使用）

1. **`actions` 段的 help 文案过时**：「生成完点「播放」试听」——
   `play` 已被白名单去掉，而且合成完会自动跳「结果」页。这句会误导。
2. **分段模式仍画「功能」小标题**：插件把按钮搬进参数页后，这一行是纯占位。

两条都写在 `log/2026-10-22-报给宿主-参数页顺序与按钮裁剪.md` 第 11 节。

## 四、兼容性

- 宿主 v9 以下：`HOST_SLOT` 的 `value` 不认识 → 按整块处理，参数页顶部出现
  整块（标题+按钮+参数+诊断），白名单不认 → 顶部仍是五个按钮。
  能用、不崩，但按钮位置和数量是旧的。**这一版的效果需要宿主 ≥ v9.1。**
- 宿主 v10 起：全部生效。
