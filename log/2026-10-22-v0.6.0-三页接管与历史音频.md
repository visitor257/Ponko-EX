# v0.6.0：三页真正接管宿主功能块 · 历史每条独立试听/保存

> 插件：`com.litertchat.plugin.voxcpm2` · versionCode 11 / 0.6.0
> 依赖：**宿主 SDK v7**（`API_VERSION = 7`，宿主提交 `3f2b69c`）
> 产物：`dist/Ponko-EX_VoxCPM2_release.apk` 4,674,947 B
> sha256 `d737e5a23e7987c5ab2e6cc2715427c0ec8659b0c336482e4e8e080ca50c6511`

## 一句话

宿主把 v7 的三件事给了（`HOST_SLOT` / `GROUP_START.value` / `onAudioFile`），
插件这版全部接上：**参数页里直接有「合成语音」，诊断和日志默认收起，历史每一条都有自己的播放和保存**。

## 改了什么

### 1. 「参数」页顶部挖 `HOST_SLOT`

```kotlin
items += UiItem(key = "tab_param", type = UiType.TAB, label = "参数")
items += UiItem(key = "host", type = UiType.HOST_SLOT)   // ★ 宿主功能块画这儿
```

那一块是宿主画的：加载 / 合成语音 / 播放 / 停止 / 保存 + 目标文本 / 模式 /
参考音频 / 逐字稿 / 种子 / 线程 / CPU-GPU + 进度提示 + 诊断。

**为什么不自己画那排按钮**：按钮背后是宿主状态机（引擎就绪、正在合成、参考音频 FD、
存到音乐库），插件重画就得把这些也搬过来，两边各存一份必然打架。这里只换挂载点，逻辑仍只有一份。

于是页面结构变成：

```
返回 / 标题
【tabs】模型 | 参数 | 结果          ← 顶部不再有那一大块，tabs 可左右滑
  参数：宿主功能块（含合成语音）
        插件默认值：语音设计描述 / CFG / 扩散步数
        本次推理：进度条 + 上次参数 + 上次耗时
        插件内部状态 ▸（收起）
        运行日志 ▸（收起）
  结果：这次的结果（播放条）
        推理历史 5 条 —— 每条一个播放条（播的是它自己）
```

### 2. 种子 / 线程：删掉插件自己那两个输入框

以前两套值：插件页填了种子 → 又去宿主改「种子」→ 没反应（插件的优先）。
现在宿主的参数区就在同一页里，用户看到的是一个控件，实际也只有一份值：

- 种子 → `SynthesisRequest.seed`，`0` = 随机
- 线程 → `EngineConfig.threads`，改完下次加载引擎生效

连带删掉 `seedText` / `threadsText` / `seedHint` / `threadsHint` / `KEY_SEED` / `KEY_THREADS`
和 `seedOverride()` / `threadsOverride()`。插件持久化的旧值不再读取（不影响功能）。

**cfg / 扩散步数没删**：宿主 `PreviewParams` 故意不暴露这两个（"该插件自己暴露"），
所以仍归插件，宿主传来的 `req.cfg` / `req.timesteps` 一直是 0，插件值生效。

### 3. 诊断 / 日志默认收起

```kotlin
UiItem(key = "g_diag", type = GROUP_START, label = "插件内部状态", value = "collapsed")
UiItem(key = "g_log",  type = GROUP_START, label = "运行日志",     value = "collapsed")
```

原来插件自己那个「诊断信息」组和宿主的诊断区**重复**，而且默认展开。
现在分组改名「插件内部状态」（设备 / 引擎 / 内部状态快照），宿主的「诊断信息」管 `debugInfo` + 最后一条错误。

### 4. 历史每条独立试听 / 保存（v7 的 `onAudioFile`）

合成成功后：

1. `out_<ts>.wav`（宿主那份）**另存**到 `filesDir/hist/h$index.wav`
2. `notifyAudioFile("h${index}_audio", file)` 交给宿主绑定到那一行
3. `Record.hasAudio = true`，`notifySchemaChanged()` 后结果页才画出那条播放条

```kotlin
if (r.hasAudio) {
    items += UiItem(key = historyAudioKey(r.index), type = UiType.AUDIO, label = "#${r.index} 试听")
}
```

- **只画真的送过文件的**：没送成功的画出来只会放最新那条，那是骗人
- 同一 key 再送 = 替换（宿主会删旧文件）
- 记录被挤出 5 条上限时 `dropHistoryAudio(index)` 删文件
- `onCreate` 清空 `filesDir/hist/`：历史清单只在内存，进程新建时它必然是空的，
  上一轮的音频没人能播了
- 「保存」存的是**那一条**（宿主按 key 给每条配了保存按钮）

## 踩到 / 避开的坑

- **`rememberAudioForHistory` 必须在 `notifySchemaChanged()` 之前**：
  播放条是画给 `hasAudio = true` 的记录，顺序反了第一条会少一个播放条
- **复制 + Binder 回调放锁外**：IO 和跨进程调用不能占着 `historyLock`
- 插件不能自己 close 交出去的 FD（宿主读完负责关，和 `notifyImage` 一样）
- `HOST_SLOT` 在 v6 宿主的降级：`unknownItem()` 画一个小灰框，功能块仍在顶部、照旧可用

## 未验证（等真机）

- 三页左右滑的手感（宿主 v5 的 ViewPager，最外层才可滑）
- `HOST_SLOT` 落进「参数」页后的滚动位置：页面变短了，日志收起后是否还需要滚

- 导入 1.7 GB 模型的耗时（沿上版未验）
