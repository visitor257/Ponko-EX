# SDK v11 核对 · 宿主不再替插件做决定

> 宿主提交 `a2eedf5`（2026-10-23 13:06），`API_VERSION` 10 → 11。
> `Ponko-2.0.0.apk`（13:05 构建）已含这一版：dex 里 `onImageWithKey` 在、
> 旧的 `scrollLogsToBottomIn` 已删、`saveLogScrolls` / `restoreLogScrolls` 已在。

## 一、这一版改了什么

主题只有一句：**插件是页面的作者，它没要求的动作宿主不加**。

| 原来 | 现在 |
|---|---|
| 日志框一渲染就滚到底 | 不动 |
| 切标签页就把该页所有日志框滚到底 | 记下位置 + 是否在底部，切回来放回原位 |
| `patch` 找不到 key 时，页面只有一个日志框就写进去 | 丢弃 + 一行日志列出可用 key |
| 送图没带 key 贴到第一张 | 只有恰好一张图才贴，多图丢弃；新增 `onImageWithKey` |
| 日志追加时无条件拉回整页滚动 | 只在日志框自己跟到底时才拉 |
| `refresh` 重画后滚动位置丢失 | 记住 scrollY，重画完放回去 |

## 二、对 0.7.0 逐条对账

| 宿主改动 | 插件是否受影响 | 依据 |
|---|---|---|
| 渲染不滚到底 | 轻微 | 「运行日志」组默认 `collapsed`，展开时停在第一行（见第三节） |
| 切页保留日志位置 | 无影响（正向） | 插件没有依赖"切回来看到最新" |
| `patch` 逐 key，不再回退 | **无影响** | 三个 key 都是真 key：`log_body` / `dl_progress` / `infer_progress`，均在 schema 里；且 `refresh` 时宿主会清索引，插件不早于渲染发 patch |
| 送图不再猜第一张 | 无关 | 插件没有 IMAGE 控件 |
| 拉回外层滚动收窄 | 正向 | 正是之前报告的「页面被日志拽走」 |
| `refresh` 恢复 scrollY | **当时判断为正，实为坑** | 见第六节：v12 证明这段恢复执行太早，反而制造了「点『加载』跳到最顶」 |

**结论：0.7.0 的二进制不需要改。** 插件侧没有一条逻辑建立在被删掉的"猜"上：

- 日志推送本来就是 `append=true` 语义（首行整段、之后逐段追加，裁剪时才 `false` 整替换），
  和宿主"跟随新内容"的契约一致
- 首行推送时 `body` 为空、`max=0`，`isAtBottom` 恒为真 → 仍会跟到底
- 自动跳结果页用的是显式 `notifySelectTab`（v8），不是靠宿主猜

## 三、一条体验变化（已单独报给宿主）

日志组的 `LOG` 控件高度固定 `LOG_HEIGHT_DP`，渲染时宿主**不再**滚到底。
插件侧没有"渲染完成"回调，`GROUP` 展开也没有回调，所以：

> 推理结束、日志静止时用户展开「运行日志」，看到的是**第一行**（最早的一条），
> 不是最新的一条。

推理进行中展开则没问题——下一条 `append` 就会跟到底。

插件侧**不去绕**这件事：能想到的办法（渲染后补发一次空 `patch(append=true)` 骗过
`isAtBottom`，或倒序输出日志）都是滥用控件语义，宿主一旦收紧就静默失效。
正确的修法在宿主：折叠组从收起变展开时，若该日志框没有用户手动滚动过的记录，跟随到底。

## 六、v12 更正（`ad90e3f`，15:26 的 APK）

我在这份文档第二节把 `refresh` 恢复 scrollY 判成"根因修复"，**这个判断是错的**。
宿主自己复查后（v12）认定它是两条错误，整套机制已经删掉。

### 错在哪

1. **时机错**：恢复动作挂在 `View.post` 上。`post` 只保证"下一轮消息循环"，
   不保证 measure/layout 跑过 —— 那时 child 高度还是 0，`scrollTo` 被夹成 0。
   表现就是用户报的「点一下加载，页面跳到最顶」。
2. **更根本：不该宿主做**。重画后停在哪是页面作者的决定。v11 刚删掉六个"顺手"行为，
   转头又加了一个同类的。

删掉之后的结论很干净：`removeAllViews()` 只 requestLayout，同帧内 `addView` 补回内容，
帧末 `mScrollY` 仍然有效 —— **Android 本来就保住了位置**，那层干预纯属多余。
日志框的位置保存/恢复（v11 加的 `saveLogScrolls` / `restoreLogScrolls`）一起删了。

### 新增 `notifyScrollTo(key)`（v12，transaction 13）

```kotlin
notifySchemaChanged()
notifyScrollTo("result")   // 滚到该 key 的控件，顶部对齐；找不到就留日志不猜
```

语义：滚到目标控件，让它的顶边对上 ScrollView 顶边（`smooth = true`）。
宿主用 `afterLayout`（`OnPreDrawListener` + `invalidate()` + 等 attach）保证在布局后算坐标。

同一个 `post` 太早的坑还修了三处：`stretchToTallestPage`（pager 宽度可能还是 0）、
日志跟随（`child.height` 是 setText 前的旧值）、日志跟随时的外层位置锁。

### 对本插件的实际影响

| 项 | 状态 |
|---|---|
| 点「加载模型」跳顶 | **v12 修好**，插件不用改 |
| 合成完跳「结果」页 | 外层偏移沿用参数页的值；结果页更短时会被夹到上限 → 停在偏下。想准就显式 `notifyScrollTo` |
| 日志展开停第一行 | **未变**（v12 只修了跟随的时机，没管折叠展开） |

### 所以

- 0.7.0 依然不用重编就能跑 v12（AIDL 只追加，`notifyScrollTo` 有 try/catch 兜住老宿主）
- 想要更准的跳页定位 → 出 0.7.1：`notifySelectTab(结果页)` 后加一句 `notifyScrollTo(结果页锚点)`，
  需要先重发 v12 的 SDK AAR
