# v0.7.1 · 跳结果页后回到页首

> 宿主 v12（`ad90e3f`，APK 15:26）之后的第一版插件。
> v11 那一版我判断"不用动"，结论没错；v12 删掉了 v11 那套滚动恢复，并给了
> `notifyScrollTo`，于是这里补一句显式的滚动声明。

## 一、改了什么

`jumpToResultPage()` 里翻完页再滚一下：

```kotlin
mainHandler.postDelayed({
    runCatching { notifySelectTab(GROUP_TABS, TAB_RESULT) }
    runCatching { notifyScrollTo(KEY_RES_TOP) }   // v12
}, TAB_SELECT_DELAY_MS)
```

结果页最前面加了一个 0 高度锚点：

```kotlin
items += UiItem(key = TAB_RESULT, type = UiType.TAB, label = "结果")
items += UiItem(key = KEY_RES_TOP, type = UiType.SPACER, value = "0")
```

## 二、为什么需要这一步

三页共用一个外层 `ScrollView`，而且宿主按**最高那页**给 pager 定高
（`stretchToTallestPage`）。所以在参数页滚了一半点合成、翻到结果页时：

- 外层 `scrollY` 还是参数页那个值（v12 起宿主**不再**动它，这是对的）
- 结果页内容比这个偏移短 → 屏幕上是一片空白，或者只剩历史列表

宿主不给"滚到顶部"的接口，只给"滚到某个 key"。所以需要一个位置在
**结果页页首**、又能被 `keyedViews` 登记的东西 —— 那就是 0 高度 SPACER。

### 为什么不能直接拿 `TAB_RESULT` 当锚点

宿主的 `render()` 只在**普通 item 分支**登记 `keyedViews`：

```kotlin
else -> {
    val v = renderItem(item) ?: return@forEach
    place(...)
    if (item.key.isNotBlank()) keyedViews[item.key] = v
}
```

`UiType.TAB` 走的是 `beginTab(item)`，**不登记**。所以 `notifyScrollTo("tab_result")`
只会得到一行"找不到 key"的日志，什么都不会发生。
`UiType.SPACER` 走普通分支，能被登记 —— 这就是选它的唯一理由。

## 三、时序

`notifyScrollTo` 内部用的是宿主的 `afterLayout`（`OnPreDrawListener` + `invalidate()`，
必要时等 attach），所以**不需要插件自己延时**，可以和 `notifySelectTab` 连着调。

和翻页并列时会有一点视觉叠加：纵向平滑滚动 + 横向切页动画同时进行。两者互不干扰
（不同轴向），效果是"页面一边横移一边回到顶部"。如果真机上看着乱，就把
`notifyScrollTo` 再推 250ms。

`TAB_SELECT_DELAY_MS`（250ms）保持原样 —— 它是留给宿主在 `onResult` 里落盘、
让结果页播放条变成可用的时间，不是给切页动画的。

## 四、兼容

`notifyScrollTo` 是 v12 追加的 AIDL 方法。在老宿主上调用会抛
`RemoteException`，基类内部已经 catch 并打一行 `notifyScrollTo 失败（老宿主？）`，
**翻页照常生效**。所以这里不需要判版本，也用 `runCatching` 兜一层。
