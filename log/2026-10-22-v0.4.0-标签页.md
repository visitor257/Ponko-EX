# v0.4.0：界面拆成四页（SDK v5 标签页）

宿主 `000dc77` 把 SDK 推到 v5，加了三个纯结构类型：

| 类型 | 值 | 作用 |
|---|---|---|
| `TABS_START` | 15 | 一组页签的开始，`key` 用来记住上次停在哪页 |
| `TAB` | 16 | 一页，`label` 是页签文字 |
| `TABS_END` | 17 | 组结束（`MAX_KNOWN = 17`） |

和 `GROUP_START/END` 同一套栈式写法，所以**能嵌套**。`API_VERSION = 5`，
新增 `API_WITH_TABS = 5`；`API_MAX_SUPPORTED` 也跟着到 5。
`d1e53cb` 是文档修正：把 `onImage` / `onUiPatch` 从"v5 新增"挪回 v4 —— v5 一个回调都没加。

## 为什么这次该用

插件页原本是一条长竖列：状态 → 试听 → 权重（源 + 逐文件 + 进度 + 三个按钮）→
合成参数 → 说明 → 日志（160 dp）。手机上要滚三四屏，而其中**参数改一次就很少动**，
**日志只有出问题才看**，真正每次进来都要看的只有「状态」。

所以按**使用频率**分四页，页内仍按使用顺序：

| 页 | 内容 | 理由 |
|---|---|---|
| 状态 | 引擎 / 权重 / 存储 / 设备 / 上次合成 / 提示 + 试听播放条 | 每次进来第一眼看这里 |
| 参数 | 1 · 权重、2 · 合成参数 | 改一次就很少动 |
| 说明 | 用法 + 许可 + 声音权益 | 几乎不看 |
| 日志 | 运行日志 + 清空 | 出问题才看 |

「状态」页里保留 `sec_play` 这个小节标题，因为上面是键值对、下面是控件，
没有标题会混在一起。其余三页去掉了 `SECTION` —— 页签本身就是标题。

## 两个技术点

**1. 整页重画后不会弹回第一页。** 宿主按 `TABS_START.key`（`tabs_main`）把选中项
存进 `tabSelected`，恢复动作放在 `TABS_END` 的 `finish()` 里统一做一次（那时所有
`TAB` 的 key 才齐）。插件在加载完 / 合成开始 / 合成完各调一次
`notifySchemaChanged()`，用户停在「日志」页就一直停在「日志」页。

**2. 隐藏页里的日志框。** 切页是纯 visibility，用户切走时日志框没被测量，
`isAtBottom()` 读到的高度是 0。宿主用 `settleCurrentPage()` 在切页后
（`page.post{}`）把当前页里的日志框重新滚到底 —— 这一条宿主已经处理了，
插件不用做任何事。反过来，插件在隐藏页里推日志补丁是安全的：写的是
`logBodies[key]` 那个 TextView，与可见性无关。

## 代价

插件从此报 `apiVersion = 5`。宿主从 `181dcf5` 起只拒**更旧**的插件，所以：

- **v4 宿主**：能连，日志框和播放条都正常，但**不认识 TABS_\*** ——
  三个类型逐个降级成「未知控件」文字块，页面顶部多几行方块，四页内容挤成一列。
  不崩、功能全在，只是难看。README 里写明了"要么更新 Ponko，要么留在 0.3.x"。
- **v3 及更早**（还在按区间拒绝那版）：直接拒绝绑定。
