# v0.9.0：中英双语，默认英文

宿主 v12.4 / v12.5 之后的两件事：插件页自己接了 i18n，并且把界面语言传给了插件。
这个插件本来就该有英文 —— 之前全套文案是硬编码中文，英文系统的用户看到的是
"英文宿主 + 中文插件"。

---

## 一、默认语言 = 你把哪门语言放进 `values/`

不需要任何字段，Android 的资源回落链就是"默认语言"：

```
系统语言 → 有 values-xx/ 就用 → 没有就落到 values/（兜底）
```

所以「默认英文」= `values/` 放英文、中文放 `values-zh/`。反过来就是默认中文。

⚠ **`values/` 必须存在**。只建 `values-ru/` 这类限定目录的话，中文手机上
`getString()` 抛 `Resources.NotFoundException`，插件直接崩 —— 这是唯一会崩的写法。

这套插件最终是 132 个 key，中英各一份，`values/`（英）+ `values-zh/`（中）。
键集合、重复、单边都有脚本比对：132 / 132，无重复、无单边。

## 二、为什么不用裸 `getString()`

插件自己的资源跟着**系统**语言走，而宿主从 Android 13 起可以被单独设成另一种语言
（per-app language）。那种情况下宿主界面是英文、插件却是中文，又回到混排。

宿主 v12.5 起在 bind Intent 里带 `EXTRA_HOST_LOCALE`，基类读出来暴露成
`hostLocaleTag` / `localizedContext()`，所以：

```kotlin
private fun res(): Resources {          // 按宿主语言解析，含正常的多级回落
    val tag = hostLocaleTag
    val cur = resCache
    if (cur != null && tag == resCacheTag) return cur
    val fresh = localizedContext().resources
    resCache = fresh; resCacheTag = tag
    return fresh
}
private fun s(id: Int): String = res().getString(id)
private fun s(id: Int, vararg args: Any): String = res().getString(id, *args)
```

缓存按**语言标签**失效，而不是在 `onCreate` 里算好存成字段 —— 后者是
"切完语言还是旧文案"的经典来源。宿主换语言会重新绑定、`getSettingsSchema()`
重拉，只要每次都现算，整条链路就跟着变。

## 三、数字行不翻译，用 ASCII token

跨语言最烦的是**拼接**。中文能拼、英文语序拼不回去。分两类处理：

| 类型 | 例子 | 做法 |
|---|---|---|
| 真句子 | 「还没有结果 · 到「参数」页点「开始推理」」 | 一个资源 + 位置参数 `%1$s` 两次 |
| 数字行 | `cfg 2.0 · 扩散 12 步 · 普通合成 · 3.2s/41s · RTF 12.8` | 词换成中性 token：`cfg 2.0 · steps 12 · Plain · …`，**不进资源** |

第二类改成 `cfg` / `steps` / `RTF` / `s` 这种谁看都懂的写法之后，中英共用一行代码，
不用维护两份模板，也不会因为翻译把参数名翻成另一个词。

## 四、三处"数据里不该存文案"

| 以前 | 现在 | 为什么 |
|---|---|---|
| `ModelStore.Spec.label: String`（"主干模型 BaseLM Q8_0"） | `labelRes: Int` | 数据清单是静态的，但文案要跟语言变；存 id，取的时候才解析 |
| `Version.label` / `Mirror.label` | `labelRes` | 同上；`Source.label`（"标准 Q8 · 魔搭"）直接删掉，用的时候拼 |
| `Ready.origin`（"本地导入" / "已下载 · 标准 Q8"） | 标记 `"imported"` / 版本 key | 这是**状态**不是文案；显示时过一层 `originLabel()` |

`originLabel()` 里 `else` 分支必须存在（未知标记回落原样显示），否则一个以后的
新版本会让这一行空掉。

## 五、两件顺带做对的小事

**① 宿主动作按钮也自己命名**

以前只覆盖 `ENGINE_LOAD` / `ENGINE_UNLOAD`，`REASONING` 用宿主默认文案 ——
而说明区里引用的是常量 `ACTION_REASONING = "开始推理"`。宿主做了 i18n 之后，
按钮可能叫 "Start inference"，说明区还写着中文「开始推理」，同屏两个说法。

现在四个都自己给（`action_load` / `action_unload` / `action_reasoning` / `action_stop`），
说明区引用同一个资源 id，永远一致。

⚠ `ActionLabel.MAX_LEN = 12`：**超长不截断，整个丢弃**、退回宿主默认文案。
"Release model" 13 个字符 → 改 `Unload`。这种坑不报错，只是那个按钮换了个说法。

**② 前台服务通知**

基类 `notificationText()` 的默认文案是**中文硬编码**，因为 SDK 没有 `res/` 目录
（这条手册里写了）。所以覆写它，否则英文用户的通知栏里是一句中文。

**改不了的**：通知**标题**「Ponko 插件」和渠道名「插件运行状态」在 SDK 的
`buildNotification()` / `ensureChannel()` 里，插件只能改正文。留给宿主。

## 六、关于文档改成 `res/raw`

v12.3 的 `ponko.about` 支持两种写法，之前用的是 `android:value` 行内字符串。
manifest 里的行内字符串**没法跟语言变**，所以改成：

```xml
<meta-data android:name="ponko.about" android:resource="@raw/about" />
```

`res/raw/about.txt`（英）+ `res/raw-zh/about.txt`（中）。打出来的 APK 里确认过
`raw/about` 有两份文件（`(file)` 和 `(zh) (file)`）。

## 七、日志**没有**翻译

`logLine()` 那 35 处仍是中文。理由和宿主一致：那是诊断输出，单一语言才便于
grep / 对照复现；翻一份等于以后每次改日志都要改两处。界面上的标签、状态、
说明、错误、通知正文都翻了，日志留着中文。

（用户如果哪天觉得别扭，这 35 行可以整批抽资源，成本不高。）

## 八、验证

| 项 | 结果 |
|---|---|
| 编译 | BUILD SUCCESSFUL，零警告 |
| 键一致性 | 英 132 / 中 132，无重复、无单边 |
| APK 资源 | `aapt2 dump strings` 里 `Synthesize` / `开始推理` / `Runtime log` / `运行日志` 都在（zh 133 条含 4 个 system） |
| about | `raw/about` 默认 + `(zh)` 两份都在 |
| dex | `hostLocaleTag` / `localizedContext` / `notificationText` / `originLabel` FOUND |
| AIDL | 未改动，`API_VERSION` 仍 12 |
| 签名 | v1+v2+v3 |

真机判据：系统语言设成英文 → 插件页整页英文（含卡片名、按钮、状态、说明）；
设成中文 → 全中文；设成俄文 → **落到英文**（因为 `values/` 是英文）。

## 一句话版

- **`values/` 就是默认语言**；只建 `values-xx/` 会在别的语言上崩
- per-app language 会让插件和宿主的语言对不上 → 用 `localizedContext()`，别用裸 `getString()`
- 数字行用 ASCII token（`steps 12`），能省掉一半要维护的模板
- 数据类里存 `labelRes`，不存 `label`；状态字段存标记，显示时再翻
- `ActionLabel.MAX_LEN = 12`：超长**整个丢弃**、退回宿主默认，且不报错
- SDK 没有 `res/`，所以 `PluginException` 的默认文案和通知标题天生只能中文 —— 能覆写的自己覆写
