# v0.6.3 · 推理完自动翻到「结果」页

日期：2026-10-22
上一版：v0.6.2（去掉说明文字）
宿主前提：SDK v8（宿主 `64cbe8f` + 23:23 那个 `Ponko-2.0.0.apk`）

## 为什么

用户：「推理完成后自动转跳到结果页。」

以前合成完停在参数页：进度条走满，然后什么都没有。要点「结果」才知道好了，
而「结果」正是他此刻唯一想看的东西 —— 这一步不该由用户做。

## 怎么接的

宿主 v8 给了 `notifySelectTab(groupKey, tabKey)`，插件在 `synthesizeBlocking()`
成功路径的 `notifySchemaChanged()` 之后调用：

```kotlin
notifySchemaChanged()
jumpToResultPage()      // 250 ms 后 notifySelectTab("tabs_main", "tab_result")
```

### 为什么要那 250 ms

基类是在 `synthesizeBlocking()` **return 之后**才 `callback.onResult(...)`，
而宿主是在 `onResult` 里把音频落盘、让结果页的播放条变成可用的。
如果在这里同步调 `selectTab`，宿主就会**先翻页、后拿到结果**，
用户看到的是一条空播放条（SDK 文档专门写了这个顺序）。

所以延后一小段，等 `onResult` 落到宿主那边再翻。250 ms 是保守值：
它只在合成结束这一刻发生一次，用户感觉不到，但足够让主线程处理完结果。

### 其它细节

- 失败 / 取消 / 引擎未就绪都不跳：只有真正产出音频才翻页
- 宿主 API < 8 时 `callback.selectTab` 不存在，异常被 `notifySelectTab` 自己
  catch —— 老宿主上静默无效，不会崩，也不用判版本
- `GROUP_TABS` / `TAB_RESULT` 提成常量，schema 与跳转共用一份，
  避免"改了一处 key、跳转悄悄失效"（v8 文档说拼错是不报错的）

## 这一版没做的两条

用户同一轮还提了：**参数页不要「播放」按钮**、**开始与停止合成一个按钮**。
两条都在宿主的按钮装配里（`PluginPage.kt:523`），插件只能决定整块挂哪儿，
不能决定块里有哪几个按钮。报告已更新，追加了第七、八、九节：
`log/2026-10-22-报给宿主-参数页顺序与按钮裁剪.md`

其中「合一」建议做成**真合一**（一个按钮按状态换文字和动作），理由：
两个按钮的 enabled 本来就互斥（`!speaking` / `speaking`），同一时刻只有一个能按，
合并不丢可达状态。宿主侧只需改 `app` 模块，不碰 AIDL。
